# 从一次成功的手机脚本，到独立 APK

## 1. 先弄清原流程，而不是凭印象重写

原流程的网页登录是为了获得本人账号的会话及请求所需字段，不是为了让用户手动购买。手机 ADB 调试曾用于研究活动页面，确认 178 元套餐的商品身份；这是开发取证步骤，不应变成所有使用者的必做步骤。

旧 AutoJs6 方案把登录会话安全导入手机，再用活动接口的时间校准单调时钟，到点按对应规则发送创建订单请求。成功后办理收银台/微信交接，最终付款仍由本人确认。

2026 年 9 月 30 日核对手机记录：旧 V2.4.0 在北京时间 12:00 的一场中，第一次请求返回订单已创建、金额 17800 分；随后有微信打开请求。四个核心文件与本机备份 SHA-256 一致。日志中的 payment_actions=0 表示程序没有做最后付款确认，不证明是否已经支付成功。原始账号和订单资料没有复制到本仓库。

## 2. 确定真正要交付的东西

最初独立 APK 1.0 只做倒计时和打开页面，未满足自动创建订单的目标。2.0 改为：官方页面独立登录、每人自己的会话、本机安全保存、自动读取时间与套餐、后台提交、手动付款和可读日志。1.0 留在历史发布，不拿旧版功能冒充新目标。

删去手工填活动链接/时间的旧界面、电脑导入、旧脚本复杂测试菜单和固定微信预支付操作。只保留一个固定套餐，主按钮一个启动，运行中有停止。20 秒无网络演练放进使用说明。

## 3. 把账号、商品与程序分开

账号来自当前用户主动登录；原生代码用官方账号接口核对 Cookie 对应的账号。旧账号、Cookie、CSRF、个人订单签名不能写进源码。

活动 ID、组件 ID、商品编号和 178 元价格属于这次固定适配的公开商品配置；临时 promo_token / promo_uuid 必须重新向官方取得，不能沿用开发者旧值。刷新时再次比对套餐名称、价格、编号等；变化就停止，不猜、不改买。

## 4. 搬运已验证规则，明确差异

保留旧 V2.4 的请求接口、请求字段、套餐校验、串行响应分类、3 个预构建请求和分段间隔。前 3 秒最小间隔 100 毫秒，随后到 10 秒为 300 毫秒，再后为 1000 毫秒；始终等待上一响应。仅旧代码识别的两类无订单回复可继续，没有把超时当作“再试一下”的理由。这是旧代码的客户端策略，不是平台公布的频率许可。

活动时间只精确到整数秒，所以通过多次请求形成时间区间交集，不能把一个整数秒当作毫秒精确时间。开售前校时、提前约 5.5 秒刷新并并入最新样本，按单调时钟等待。应用不会修改手机系统时间。已经开售时立即准备，使用系统可用的网络时钟，无法取得则退回系统时钟。

新程序对临近开售的商品刷新失败采取停止，不像旧脚本某些网络读失败时继续用上一次参数。付款交接改为官方收银台由本人选渠道，不复制固定微信预支付分支。详见迁移对照。

## 5. Android 实现

原生 Java 界面，浅蓝奶白配色、圆体字、贴纸标签与同人插画。布局和按钮是原生控件，图片只是装饰。首页不堆砌版本角标；说明集中在使用说明与账号/数据菜单。

MainActivity 负责登录与交互；BiliClient 核对官方账号、活动、订单；PurchaseRules 负责纯规则；PurchaseRunner 负责时间与串行流程；OfficialTransport 负责 HTTPS 和不可隐式重放；PurchaseService 负责用户主动启动的前台服务；SecureStore 加密私有数据；Diagnostics 和只读提供器管理脱敏日志。

Android 后台直接拉起界面受到限制，所以后台通过订单通知交给用户点开。没有添加悬浮窗、无障碍或全屏通知来绕过系统约束。服务不随开机启动，进程死亡后不自动补单。

## 6. 构建、测试、签名

开发需要 Windows、JDK 21、Android SDK Build Tools 35、Android 35 android.jar 和 Node.js。普通用户不需要它们。本仓库使用精简构建脚本，不要求 Android Studio / Gradle。

先运行 node tools/fetch-deps.mjs，下载锁定版本并校验 dependencies.lock.json。再用 PowerShell 运行 tools/build.ps1，传入 BuildTools、AndroidJar 和 Jdk 的本机绝对路径。SDK 路径使用纯英文，避免 Windows SDK 工具对中文路径的兼容问题。

构建会执行 77 项合成响应检查，然后编译 Java、资源与 DEX，打包字体和许可、对齐并签名。首次构建在仓库外生成自己的签名；后续更新保留同一把私钥。不要上传签名密码，丢失密钥通常意味着不能直接覆盖原安装包。

tests/DeviceSelfTest.java 是独立的、同签名测试 APK，只使用隔离的合成数据检查 Keystore 和状态机，不应随用户版本发布。当前手机拦截该测试包安装，所以未将其写成已通过。

## 7. 成品必须带哪些说明

至少写清：功能与适配范围、Android/iOS 支持情况、自动创建订单和手动付款的区别、权限用途、处理的数据与保存位置、网络对象、退出与清空办法、错误处理、费用与库存不保证、平台规则边界、第三方依赖与素材许可、版本测试范围、下载与签名校验方式、反馈渠道。

本项目不收费、不代付；套餐费用由用户向官方付款。不能把“没有开发者后台”宣传为“完全不联网”，也不能将“未发现恶意代码”宣传成“百分之百安全”。

## 8. 发布并持续维护

只打包受版本控制的源文件；排除旧会话、日志、私人截图、订单、签名密钥和构建缓存。建立版本标签，发布 APK、A4 PDF、源码 ZIP、SHA-256 校验清单；上传后检查资产摘要与大小，记录实际测试的设备和版本。

真实开售、付款交接及多机型尚未验证，所以使用预发布标记。后续若平台接口变化，先更新测试及隐私说明，再发布版本，不让程序默默换商品或扩大权限。
