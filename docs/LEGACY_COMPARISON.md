# 旧脚本与独立 APK 的对应关系

旧手机程序为 AutoJs6 V2.4，独立 APK 为 2.0.0，版本号属于两个不同产品阶段。旧脚本成功的请求规则是迁移依据，但新 APK 的真实下单全链路仍待验证。

| 环节 | 旧手机 V2.4 | 独立 APK 2.0 |
| --- | --- | --- |
| 获取账号 | 电脑网页登录后，受保护地导入手机 | 每位用户在本应用官方网页登录，账号接口核对后本机加密 |
| 核对套餐 | 开发时 ADB 研究页面、提取固定 178 元商品身份 | 固定公开商品身份已经适配；自动获取临时参数，无需用户再连电脑核对 |
| 时间 | 官方 current_time 多样本区间校准，单调时钟调度 | 同样的区间方法、临近刷新并入样本与预构建请求 |
| 创建订单 | 对应活动 POST，自己的 Cookie/CSRF | 同一活动与字段结构，只使用当前登录者信息 |
| 重试 | 指定“未开售”“43055 活动繁忙”无订单回复；分段串行 | 保留该规则；未知结果、限流、验证、售罄不重发 |
| 刷新失败 | 部分瞬态读失败允许沿用上次已验证参数 | 本版停止，不继续用旧参数；这是明确的差异 |
| 支付交接 | 查询微信渠道、申请预支付并拉起微信，最后本人付款 | 打开官方收银台，用户自行选择其支持的支付方式；不固定微信，不代付款 |
| 后台 | AutoJs6、脚本宿主和相关权限 | 用户启动的原生前台服务、通知和唤醒锁；无无障碍权限 |
| 错误日志 | 手机诊断文件 | 本机脱敏日志，可在 App 中阅读、清空或主动导出 |
| 保留个人资料 | 旧备份由原所有者保管 | 不随公开代码、APK、邮件或源码 ZIP 发布 |

2026 年 9 月 30 日的旧程序成功证据：第一笔返回创建订单、17800 分，随后请求微信交接。四个核心文件与电脑备份 SHA-256 相同。旧记录中的“程序支付动作 0”不能用来判断用户最终有没有付款。

最初 APK 1.0 只是前台倒计时和打开页面，没有上述自动创建订单能力。它是历史版本，不应再作为当前目标的完成依据。旧版 APK 与说明保留在 v1.0.0 历史发布。
